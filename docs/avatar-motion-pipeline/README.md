# DateVibe Room Avatar Motion Pipeline

This folder tracks candidate production inputs for DateVibe's 2.5D room avatar
motion assets.

## Motion v1 Scope

Motion v1 is female default only:

- `Walk front`: 4 frames, `1024x384`, `120ms`, looping.
- `Sit front`: 1 frame, `256x384`, `120ms` metadata, static/non-looping.
- Per-frame canvas: `256x384`, transparent RGBA.
- Shared centerline: `x=128`.
- Shared feet baseline: `y=360`.
- Required layers: base, face, hairBack, hairFront, top, bottom, shoes.

Excluded from Motion v1:

- male presets
- non-default avatar items
- gesture/delight motions
- waving
- dancing

Do not import any generated frames into app assets or `ROOM_AVATAR_CATALOG`
until all required female default Walk/Sit layers pass extractor guards and
overlay QA.

## Body Motion Driver + Fitted Layers

DateVibe room avatars use a body-first 2.5D layer pipeline. For each Motion v1
motion requirement, generate the female `base` layer first. That strip is the
motion driver: it defines the body pose, feet contact, centerline, baseline,
frame count, and frame duration for the female default preset.

All other layers are fitted layers:

- face
- hair back/front
- tops
- bottoms
- shoes
- accessories

Generate fitted layers against the matching body motion driver strip. A fitted
layer must not include body pixels or merged outfit pixels from other layers; it
must only contain its own transparent layer while following the driver pose. This
keeps clothing aligned without creating a second avatar system.

The manifest exposes this contract per plan:

- `fitRole`: `motionDriver` or `fittedLayer`
- `fitProfileId`: female room-avatar fit profile
- `motionDriverLayerId`
- `motionDriverStripPath`
- `requiresMotionDriverReference`
- `frameDurationMs`: `120`
- `loop`: `true` for Walk front, `false` for Sit front

If a fitted layer is generated before its driver strip exists, treat it as a
draft only. Do not import it into the catalog until the whole motion set shares
the same rig, fit profile, frame count, frame duration, baseline, and centerline.

## Overlay QA Gate

Before catalog import, create an overlay QA sheet that shows:

- full composed female default avatar frame 01
- full composed female default avatar at one Walk motion frame
- base plus each fitted layer over frame 01
- base plus each fitted layer over at least one motion frame

Stop before catalog import if any output shows cropped pixels, layer drift,
clothing/body separation, hair/face/shoe drift, background contamination, or a
robotic/sliding/non-premium 4-frame walk.

For the base-driver approval step, stop before fitted layers if the base looks
ugly, placeholder-like, non-premium, cropped, sliding, distorted, or unable to
read as a grounded DateVibe avatar. If the 4-frame walk cannot look premium,
pause and propose a 6-frame upgrade before generating fitted layers.

Extract frames from a generated strip only after it passes the import-prep
guards:

```bash
python3 apps/mobile/scripts/extract_room_avatar_motion_frames.py \
  --asset-prefix room_avatar_hair_female_blonde_long_back_v2_walking_front \
  --strip docs/avatar-motion-pipeline/room_avatar_hair_female_blonde_long_back_v2_walking_front_strip.png
```

By default this refuses blank frame slots and refuses animated strips where all
frames are identical to frame 01. Extracted frames go to
`docs/avatar-motion-pipeline/extracted-frames/` and are still staging files, not
catalog imports.

## Generation Prompt

Edit the provided transparent reference canvas into a single horizontal 4-frame spritesheet.

The existing sprite in the leftmost slot is the anchor frame and must remain the same layer:
- same character rig
- same facing direction: front
- same silhouette family
- same palette family
- same proportions
- same hair shape and readable strand mass
- transparent background

Composition:
- exactly one row of 4 equal `256x384` frame slots
- no extra characters
- no labels
- no scenery
- no poster layout

Action:
- subtle front-facing walk cycle for this hair-back layer
- frame 1 should match the shipped seed
- frames 2-4 should preserve the same baseline and centerline

Style:
- production mobile avatar layer
- clean transparent PNG
- no concept-art background

## Import Gate

Do not connect generated frames to `ROOM_AVATAR_CATALOG` until all required layers for the same motion state share:

- `datevibe_2_5d_layered_v1`
- matching `fitProfileId`
- identical frame count
- identical frame duration
- stable `256x384` transparent canvas
- passed overlay QA for base plus every fitted layer
